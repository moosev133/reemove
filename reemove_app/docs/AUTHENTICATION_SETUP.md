# Authentication provider and operations setup

## 1. Firebase projects and FlutterFire

Use isolated development, staging, and production Firebase projects. Generate platform configuration from the project owner's accounts:

```bash
flutterfire configure --project YOUR_PROJECT_ID
```

Do not commit service-account keys, Apple private keys, private signing material, or local App Check debug tokens.

## 2. Enable providers

In Firebase Authentication, enable:

- Email/Password
- Google
- Apple

Set the public support email and verify every web domain used by the application.

## 3. Email/password

Configure sender identity, verification and password-reset templates, authorized action-link domains, localization, password policy, and email-enumeration protection. ReeMove already uses generic reset confirmation copy.

## 4. Google

### Android

- Register the Android application ID.
- Add SHA-1 and SHA-256 fingerprints for development, staging, and production signing keys.
- Download the refreshed Android Firebase configuration.
- Confirm the generated OAuth clients for every signing identity.

### iOS

- Register the bundle ID.
- Add the reversed client-ID URL scheme generated by Firebase.
- Download the refreshed Apple Firebase configuration.

### Native server client ID

Pass the web OAuth client ID to native Google sign-in:

```bash
--dart-define=GOOGLE_SERVER_CLIENT_ID=YOUR_WEB_CLIENT_ID
```

Web uses Firebase provider popups; native uses `google_sign_in` and exchanges the returned ID token for a Firebase credential.

## 5. Apple

- Enable Sign in with Apple for the App ID.
- Add the iOS capability.
- Create the service ID and private key required for Android/web OAuth redirect support.
- Configure Firebase with the Apple team ID, key ID, private key, and service ID.
- Register Firebase's callback URL with Apple.
- Establish a key-rotation owner and procedure.

Apple may return a user's name only on the first authorization. ReeMove therefore treats server provisioning and username/display-name setup as authoritative.

## 6. Cloud Functions region and deployment

The app defaults to `europe-west1`; keep the client and deployed Functions aligned:

```bash
--dart-define=FIREBASE_FUNCTIONS_REGION=europe-west1
firebase deploy --only functions
```

Node.js 22 is required.

## 7. App Check

- Development: debug providers and registered debug tokens.
- Android production: Play Integrity.
- Apple production: App Attest with DeviceCheck fallback.
- Web production: reCAPTCHA v3.

Enable enforcement only after staging telemetry confirms every supported client sends valid tokens. Callable authentication operations already share App Check-enforced options.

## 8. Authentication analytics

Analytics is off by default and always off against emulators. Enable it only after project/consent/privacy setup is complete:

```bash
--dart-define=ENABLE_ANALYTICS=true
```

Authentication events include only action names and provider categories. Configure retention, data sharing, audiences, and store privacy declarations in the real Firebase/Google Analytics project.

## 9. Firestore TTL for rate limits

Configure a Firestore TTL policy on:

```text
Collection group: rate_limits
Field: expiresAt
```

TTL cleanup is operational hygiene; rate-limit correctness does not depend on immediate deletion.

## 10. Scheduler and billing

`retryAccountDeletions` runs every six hours. Ensure the Firebase/Google Cloud project has the required billing plan, Scheduler support, permissions, and alerting. Assign an operational owner for failed deletion records.

## 11. Local emulators

Install dependencies and start the Auth/Firestore seed workflow:

```bash
npm --prefix functions ci
npm --prefix firebase_tests ci
npm run seed:emulator
```

Demo-only identity:

```text
Email: athlete@demo.reemove.app
Password: ReeMoveDemo123!
UID: demo-athlete
```

Run Flutter with:

```bash
flutter run \
  --dart-define=APP_FLAVOR=development \
  --dart-define=ENABLE_APP_CHECK=false \
  --dart-define=ENABLE_ANALYTICS=false \
  --dart-define=USE_FIREBASE_EMULATORS=true \
  --dart-define=FIREBASE_EMULATOR_HOST=127.0.0.1
```

## 12. Pre-release provider matrix

Test each supported platform and environment for:

- New email registration, duplicate email, weak password, verification, reset, and cancellation.
- New Google/Apple account, returning account, cancellation, disabled account, and credential collision.
- Linking each provider to an existing account and rejecting credentials owned by another account.
- Reauthentication before session revocation and deletion.
- Refresh-token revocation across at least two real devices.
- Username collision under concurrent requests.
- App Check rejection for untrusted clients.
- Account deletion retry after an intentionally simulated transient backend failure.

## 13. Secret and credential ownership

Document owners and rotation schedules for Android signing keys, iOS distribution certificates, Apple Sign-in key, OAuth clients, Firebase service accounts, App Check keys, and release CI credentials. Never store them in this repository.
